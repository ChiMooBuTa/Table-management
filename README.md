# ระบบจัดการที่นั่งและเช็คอินแขกงานแต่ง

เว็บแบบ static ใช้งานบน GitHub Pages ข้อมูลซิงก์ข้ามเครื่องด้วย Firebase Realtime Database ไม่ต้อง build

| หน้า | ลิงก์ | ทำอะไรได้ |
|---|---|---|
| ผู้ดูแล | `#admin` | เช็คอิน, แก้ผังโต๊ะ, เพิ่ม/แก้/ลบแขก, นำเข้า/ส่งออก |
| หน้าประตู | `#door` | เช็คอิน, เพิ่มแขกหน้างาน, เปลี่ยนโต๊ะ, ดูผังโต๊ะ |
| ของชำร่วย | `#gift` | ค้นหาแขกและมอบของชำร่วย คนละ 1 ชิ้น (ยกเลิกได้เฉพาะ admin) |
| ดูข้อมูล | `#viewer` | ดูรายชื่อ สถานะ และผังโต๊ะ |

## ขั้นที่ 1 สร้าง Firebase (ทำครั้งเดียว)

1. เปิด https://console.firebase.google.com กด **Create a project**
2. เมนู **Realtime Database** > **Create Database** เลือก Singapore (asia-southeast1) เริ่มแบบ **locked mode**
3. แท็บ **Rules** ลบของเดิม วางเนื้อหาไฟล์ `database.rules.json` แล้วกด **Publish**
4. เมนู **Authentication** > **Get started** > **Sign-in method** เปิด **Email/Password**
5. แท็บ **Users** > **Add user** สร้างบัญชี เช่น
   - `admin@wedding.local` (ผู้ดูแล)
   - `door@wedding.local` (ทีมหน้าประตู ใช้ร่วมกันหลายเครื่องได้)
   - `gift@wedding.local` (ทีมของชำร่วย)
   - `viewer@wedding.local` (ผู้ดู)

   ใช้รหัสผ่านที่เดายาก และคัดลอกค่า **User UID** ของแต่ละบัญชีไว้
6. กลับไป **Realtime Database** แท็บ **Data** เพิ่มข้อมูลสิทธิ์ตามโครงสร้างนี้ (กด `+` ที่รากฐานข้อมูล ใช้ UID จริงเป็นชื่อคีย์)

   ```
   roles
     ├─ <UID ของ admin>  : "admin"
     ├─ <UID ของ door>   : "door"
     ├─ <UID ของ gift>   : "gift"
     └─ <UID ของ viewer> : "viewer"
   ```
7. **Project settings** (รูปเฟือง) > **Your apps** > กดไอคอนเว็บ `</>` > ลงทะเบียนแอป แล้วคัดลอก `firebaseConfig`

## ขั้นที่ 2 ใส่ค่าใน config.js

แทน `export const firebaseConfig = null;` ด้วยค่าที่คัดลอกมา โดยต้องมี `databaseURL` (ถ้าไม่มี ให้คัดลอก URL จากหน้า Realtime Database) และแก้ `EVENT_NAME` เป็นชื่องาน

`apiKey` ของ Firebase เว็บเปิดเผยได้ ความปลอดภัยของข้อมูลมาจากการเข้าสู่ระบบและ Rules ในขั้นที่ 1

## ขั้นที่ 3 อัปขึ้น GitHub Pages

1. สร้าง repository ใหม่บน GitHub
2. **Add file > Upload files** ลากไฟล์และโฟลเดอร์ `js` ทั้งหมดขึ้นไป (`index.html` ต้องอยู่ชั้นนอกสุด) แล้วกด **Commit changes**
3. **Settings > Pages** > Source: **Deploy from a branch** > Branch: `main` / `(root)` > **Save**
4. รอสักครู่ เปิด `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/#admin`
5. ใน Firebase **Authentication > Settings > Authorized domains** เพิ่ม `<ชื่อผู้ใช้>.github.io`

**ห้ามอัปไฟล์รายชื่อแขกจริง (.xlsx / .json) ขึ้น GitHub** ให้นำเข้าผ่านหน้า `#admin` เท่านั้น

## ธีมสีและสัญลักษณ์งาน

`#admin` > **ธีมและโลโก้** เลือกชุดสีหรือกำหนดสีเอง ใส่ชื่องาน อัปโหลดโลโก้ (PNG/JPG/WebP) หรือใช้ข้อความ/อีโมจิ แล้วกด **บันทึกธีม** ทุกเครื่องจะเปลี่ยนตาม

## การใช้งาน

1. `#admin` > **นำเข้า / ส่งออก** > เลือกไฟล์ Excel (ดูรูปแบบจาก `sample-guests.xlsx`)
2. **ผังโต๊ะ** > กด **สร้างโต๊ะจากรายชื่อ** แล้วลากจัดวาง เพิ่มเวที ทางเดิน ประตู
3. วันงานให้ทีมหน้าประตูเปิด `#door` และทีมของชำร่วยเปิด `#gift` แล้วเข้าสู่ระบบ

### รูปแบบไฟล์ Excel

`ลำดับ | ชื่อสกุลไทย | ชื่อสกุลEng | ตำแหน่ง | ความสัมพันธ์ | สถานะเช็คอิน | โต๊ะ | ของชำร่วย | หน้างาน`

- หน้างาน: `ใช่` สำหรับแขกที่เพิ่มวันงาน (ไม่บังคับ)

- ของชำร่วย: `รับแล้ว` หรือ `ยังไม่รับ` (คอลัมน์นี้ไม่บังคับ การนำเข้าแบบรวมจะไม่ลบประวัติการรับเดิม)

- สถานะ: `เช็คอินแล้ว` หรือ `ยังไม่เช็คอิน` (เว้นว่างได้)
- นำเข้าแบบ **รวม** จะจับคู่ด้วยชื่อไทยและอังกฤษ ถ้าช่องสถานะหรือโต๊ะว่างจะคงค่าเดิม แต่ถ้าไฟล์ระบุ `ยังไม่เช็คอิน` จะเขียนทับสถานะเดิม
- ไฟล์ส่งออกมีชีต `รายชื่อแขก` และ `ผังโต๊ะ` นำกลับเข้ามาได้
- รองรับ `.xlsx` และ `.csv` (ไฟล์ `.xls` รุ่นเก่าให้บันทึกเป็น `.xlsx` ก่อน)

## ข้อควรรู้ก่อนวันงาน

- แพ็กเกจฟรี (Spark) ของ Realtime Database รองรับการเชื่อมต่อพร้อมกันสูงสุด 100 (1 แท็บ = 1 การเชื่อมต่อ)
- ถ้าเน็ตหลุด การเช็คอินจะรอส่งเมื่อกลับมาออนไลน์ **ห้ามปิดหรือรีเฟรชหน้า** ขณะสถานะเป็นออฟไลน์ ควรมีเน็ตมือถือสำรอง
- ส่งออกข้อมูลสำรองก่อนเริ่มงานและหลังจบงาน
- หลังจบงาน ควรลบข้อมูลแขกและบัญชีที่ไม่ใช้
- ทดลองก่อนตั้งค่า Firebase ได้ (`firebaseConfig = null`) โดยรันผ่านเว็บเซิร์ฟเวอร์ เช่น `python -m http.server` แล้วเปิด `http://localhost:8000` (ดับเบิลคลิกเปิด `index.html` ตรง ๆ ไม่ได้)
